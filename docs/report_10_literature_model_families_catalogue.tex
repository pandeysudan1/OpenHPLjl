\begin{abstract}
This report records how the literature model families identified in Report 9
have been mapped into the OpenHPLjl source tree. It distinguishes baseline
models, runnable prototypes, and planned high-fidelity families that require
additional interfaces, data, or spatial discretization.
\end{abstract}

\section{Checkpoint}
The previous checkpoint established the core chain
\[
\text{Reservoir}\rightarrow\text{RigidPipe}\rightarrow\text{SurgeTank}
\rightarrow\text{Turbine}\rightarrow\text{Shaft}\rightarrow\text{Generator}
\rightarrow\text{Grid}.
\]
The current branch expands each folder into a literature-guided model family.

\section{Status convention}
\begin{itemize}
\item \textbf{baseline}: implemented in v0.1.0-alpha.1.
\item \textbf{prototype}: source model or executable structural prototype added.
\item \textbf{planned}: model family documented, but production implementation
requires new interfaces, calibration data, or PDE/discretization machinery.
\end{itemize}

\section{Registry}
The branch adds \texttt{src/ModelFamilies/ModelFamilyRegistry.jl}. The registry
provides one machine-readable catalogue grouped by physical domain and tagged
with \texttt{:baseline}, \texttt{:prototype}, or \texttt{:planned}.

This is important because future tutorials, tests, and documentation can query
the same catalogue instead of duplicating model lists.

\section{Models wired into the package}
The following new families are sufficiently compatible with the current
connectors to be included directly:
\begin{itemize}
\item PhasorPort,
\item NonlinearReservoir,
\item transitional friction factor,
\item QuasiSteadyPipe,
\item TwoMassShaft,
\item model-family registry.
\end{itemize}

The higher-fidelity turbine, generator, grid, elastic-waterway, and specialized
surge-tank files are intentionally kept as prototypes/specifications until their
required data structures and interfaces are finalized.

\section{Validation rule}
A literature family is not promoted from prototype to baseline merely because a
file exists. Promotion requires:
\begin{enumerate}
\item complete governing equations,
\item parameter and unit table,
\item structural equation/unknown check,
\item analytical or limiting-case test,
\item component simulation,
\item connected-system test,
\item comparison with literature/reference behaviour.
\end{enumerate}

\section{Next implementation wave}
The preferred promotion sequence is:
\[
\text{TurbineLookup}\rightarrow
\text{ClassicalGenerator}\rightarrow
\text{SMIBGrid}\rightarrow
\text{TwoMassShaft}\rightarrow

\section*{Conclusion}
All literature families identified in Report 9 now have an explicit location in
the OpenHPLjl source architecture. The next work is no longer catalogue
creation; it is model-by-model promotion from specification to validated
ModelingToolkit implementation.
